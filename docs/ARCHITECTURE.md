# 架构：知识状态、材料和消费关系

状态：首版设计提案，配套[需求](REQUIREMENTS.md)。本文中的操作名称表示职责，尚非已发布接口。

## 组成

拟以 Python 3.12 核心库和 CLI 起步，在单机受信环境内运行。知识核心不依赖 P、特定 Agent、LLM 或向量数据库。

| 组成 | 本仓责任 | 外部边界 |
| --- | --- | --- |
| 知识核心 | 候选、知识谱系、版本状态、使用与反馈规则 | 不承担任务执行或原始观察真实性证明 |
| 本地知识存储 | 本组件对象、事件、幂等结果及待决写入 | 独占本仓 SQLite 表，不与其他组件共同写表 |
| 材料适配器 | 核对 Ledger 的准确引用并读取实际内容 | Ledger 拥有制品记录与内容；只用公共接口 |
| 审查输入边界 | 记录明确决定、主体归因、理由和目标版本 | 受信调用方负责授权，存储不能自授准入权 |
| 查询与使用入口 | 确定性筛选、准确版本读取、使用登记和效果关联 | 查询排名和使用记录均不授权行动 |

初始审查输入可与领域核心在同一包中，通过独立操作记录决定；共址不合并领域状态含义与审查决定权。没有实际生命周期需求前不再拆分治理、检索或运行记录仓库。

## 对象和状态

| 对象 | 保存内容及约束 |
| --- | --- |
| 运行材料记录 | 稳定 ID、调用来源、任务/运行引用、上下文、声称的结果、缺口与准确制品版本 |
| 候选 | 不可静默修改的经验内容、适用范围、已有材料引用；修订候选另含预期知识版本 |
| 审查记录 | 原候选与内容绑定、接受或拒绝、主体归因、理由、所依据材料；决定历史保留 |
| 知识版本 | 所属谱系、版本 ID、内容与适用范围、候选/审查来源；内容不原地覆盖 |
| 使用记录 | 消费者、任务/运行、准确知识版本、采用时上下文及状态核对结果 |
| 效果记录 | 原使用 ID、完成观察及材料引用；不能把任务成功直接解释为知识正确 |
| 退休记录 | 预期当前版本、支持材料、明确主体与理由；退出主动使用但保留历史 |

候选由待审进入接受或拒绝；接受、知识版本创建与本地成功回执在同一知识事务中提交。知识版本在创建时有效，后续可被替代或退休。同谱系任一已提交状态至多有一个有效版本。

修订接受时对预期当前版本作条件更新，旧版本退出主动查询、新版本生效与审查记录同事务提交；竞争者收到冲突，不覆盖胜出的版本。退休也核对原版本，不能把迟到决定应用到新版本。事务重放先返回已有成功结果，不能因当前版本已改变而把原成功请求重新解释成一次新操作。

初版不做跨谱系自动合并或自动重新激活。错误决定通过可追溯的新记录和受支持操作纠正，不改写已发生历史。

## Ledger 连接与恢复

采用 Ledger 的 `bounded-local-v0.1` 公共库：`initialize` 与 `open` 分离，写入使用 `execute`，定位对象使用 `get_record`，核对原请求使用 `get_operation`，实际内容使用 `read_blob` 校验读取。完整接口以[固定依赖文档](https://github.com/kongbu0621/infra-artifact-ledger/blob/58b08fa9cb188c48feec45592a0f775c7178fd7a/docs/INTERFACE_PROFILE.md)为准。

每个材料引用保存配置的 Ledger 绑定、Artifact ID、Version ID 与所用内容的摘要和大小。先核对 Version 属于指定 Artifact，再沿 ContentRoot/Manifest 定位 Blob 并读取实际字节；不从文件名、同名 ID 或 latest 推断内容。包自洽不能代替核对它属于调用方声明的任务。

调用方可以提供已存在的材料版本；若本仓适配器负责登记材料，先持久保存原请求、稳定对象 ID、幂等键和有界输入字节，再分别提交 Ledger 的创建与追加操作。确认材料版本可读后，才提交引用它的知识记录。三次提交不是一个跨库事务；已登记但尚未被知识引用的材料允许保留。

任何丢响应或提交未知都保留原身份与内容，查询原操作并核对请求指纹及结果。一次未找到不证明旧调用不会继续提交；只在调用生命周期和原接口幂等语义允许时重试相同请求。不得换 key、删除数据库或重跑原生产任务来消除不确定性。

知识本地写操作也使用作用域、操作类型、请求 ID 与规范化内容绑定，成功回执与业务状态同事务保存；不能从 Ledger 的幂等性推断知识写入已幂等。错误返回需区分未提交、已提交和未知，重启按原请求查询或接续。

知识数据库只存本组件领域对象与引用，Ledger 保存原始材料；两者不共同写同一事实。完整知识文本暂存知识库，后续若导出为制品，它是带版本的导出副本，不成为第二个可写的知识状态权威。

## 查询、使用与反馈

查询先按显式类型、范围与上下文条件确定性筛选有效知识；响应有界，返回准确版本、内容绑定和材料可用性。候选、被替代和退休版本只可从历史入口读取，不混入主动查询。首版不实现语义排名或可独立修改状态的缓存。

开始使用是单独的本地写操作：在事务中核对准确版本仍有效、适用条件匹配，并保存关联任务的稳定使用 ID。返回的知识内容与该版本一致。查询与开始使用之间发生退休或修订时，新使用应冲突；先登记成功、之后才退休时，保留原使用事实。调用方负责确保实际采用与登记对应，记录本身不证明外部业务已经执行。

完成反馈使用原使用 ID，允许原知识版本已失效，只追加该次效果与材料引用。重复提交按原请求收敛，改变反馈需显式的新更正记录，保留原内容；反馈不能恢复旧知识或自动修改当前版本。没有原使用 ID 的结果作为运行材料接收，报告无法证明原使用关联。

P 可把生产候选与运行引用交给 K，并读取 K 的知识版本；双方通过可版本化的公共数据对象连接。K 不写 P 的任务状态，P 不直接设置 K 的有效状态。适配与真实消费验证后才能宣称两端已经接通。

## 持久性、隐私与资源

知识存储采用本地 SQLite，单次领域写事务内完成状态检查、事件与幂等结果。多个进程串行写入或得到明确忙错误；不在写事务中等待 Ledger I/O。外部内容核对与本地状态检查分别记录，不声称可原子冻结跨库状态；新使用前重新确认必需材料可读，之后的可用性变化如实报告。

运行数据放在调用方指定的私有目录；一个数据库属于一个受信、隐私和保留范围。主体标签与 namespace 不提供租户隔离。本地持久化不承诺加密、密码学防篡改或任意掉电恢复。

首次实现明确文本、记录、内容读取、查询分页及重试预算。遵守 Ledger 更严格的限额，超限报错，不截断经验或悄悄减少依据。初始化与打开既有库分离；缺库、损坏或不支持的格式不能自动变成空库。

## 组合恢复

知识状态与 Ledger 分别取得一致性快照；不能仅复制活动 SQLite 主文件而忽略 WAL。知识快照和 Ledger 快照不保证同时刻，恢复到新位置后应核对绑定及声明恢复范围内的完整引用链，包括知识、审查、使用、候选、运行材料和效果记录实际引用的准确制品版本与所需内容。

缺失或损坏逐项呈现，限制依赖这些材料的准入和新使用；历史读取保留缺口。恢复检查不自动改变审查状态，不以同名材料或最新版本替代缺件。补齐并重新核对后才能声明该范围完整；这项组合检查不要求重做 Ledger 已完成的 A2 任务。
