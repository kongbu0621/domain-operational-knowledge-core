# 架构：知识状态、材料和消费关系

状态：本文保留首版完整架构，配套[需求](REQUIREMENTS.md)。当前 `0.1.0a3` 已实现材料、候选、审查、查询、使用/反馈与修订/退休；精确接口见[公共接口](INTERFACE.md)。P 仓已有公共接口适配，完成真实采用与结果回流、明确学习候选投递及后续知识修订采用；组合恢复已覆盖五个安装态合成窗口和已有真实试点的历史只读对账，见[组合恢复核对](https://github.com/kongbu0621/control-production-plane/blob/main/docs/COMBINED_RECOVERY.md)。本仓尚无组合快照、路径迁移或恢复副本启用接口；受信维护者已完成同机原路径的人工受控切换及新采用/反馈，具体范围见上述组合恢复记录，跨机切换和自动启用仍待后续。

## 组成

当前采用 Python 3.12 核心库和 CLI，在单机受信环境内运行。知识核心不依赖 P、特定 Agent、LLM 或向量数据库。

当前包内 model 校验有界输入，database 管理 K 的 SQLite 事务和身份，records 核对当前操作涉及的持久记录内容与索引绑定，ledger 只调用 Ledger 公共 API，service 协调公共接口、材料/候选/审查/查询，lifecycle 实现使用、反馈与退休的事务前提，cli 处理文件与 JSON。publish_material 先提交待决输入，再完成 Ledger create/append，最后提交 K 引用和回执；进程退出后以原请求接续。审查决定、候选终态、知识版本切换与回执在同一 K 事务内提交。complete_use/correct_feedback 复用材料发布路径：先预留原反馈位置和材料身份，后写 Ledger，最后在一个 K 事务内保存材料、反馈、更正关系与回执并释放预留。

新库使用 SQLite 格式 2；格式 1 可继续读取和执行原有材料/候选操作，使用新增生命周期操作前显式 upgrade。升级只增加表和索引并更新格式号，在单个 K 事务中完成；身份文件、原记录、回执、事件和 Ledger 均不重写。旧版程序不支持格式 2，升级应先停用旧版写入者；本次不升级任何用户运行库。

| 组成 | 本仓责任 | 外部边界 |
| --- | --- | --- |
| 知识核心 | 候选、知识谱系、版本状态、使用与反馈规则 | 不承担任务执行或原始观察真实性证明 |
| 本地知识存储 | 本组件对象、事件、幂等结果及待决写入 | 独占本仓 SQLite 表，不与其他组件共同写表 |
| 材料适配器 | 核对 Ledger 的准确引用并读取实际内容 | Ledger 拥有制品记录与内容；只用公共接口 |
| 审查输入边界 | 记录明确决定、主体归因、理由和目标版本 | 受信调用方负责授权，存储不能自授准入权 |
| 查询与使用入口 | 确定性筛选、准确版本读取、使用登记和效果关联 | 查询排名和使用记录均不授权行动 |

初始审查输入可与领域核心在同一包中，通过独立操作记录决定；共址不合并领域状态含义与审查决定权。没有实际生命周期需求前不再拆分治理、检索或运行记录仓库。

## 对象和状态

| 对象 | 保存内容及约束 |
| --- | --- |
| 运行材料记录 | 稳定 ID、调用来源、任务/运行引用、上下文、声称的结果、缺口与准确制品版本 |
| 候选 | 来源作用域内的稳定提案身份、不可静默修改的经验内容、适用范围、已有材料引用；修订候选另含预期知识版本 |
| 审查记录 | 原候选与内容绑定、接受或拒绝、主体归因、理由、所依据材料；决定历史保留 |
| 知识版本 | 所属谱系、版本 ID、内容与适用范围、候选/审查来源；内容不原地覆盖 |
| 使用记录 | 消费者、任务/运行、准确知识版本、采用时上下文及状态核对结果 |
| 效果记录 | 原使用 ID、完成观察对应的运行材料记录、更正关系；不能把任务成功直接解释为知识正确 |
| 退休记录 | 预期当前版本、支持材料、明确主体与理由；退出主动使用但保留历史 |

候选由待审进入接受或拒绝；接受、知识版本创建与本地成功回执在同一知识事务中提交。知识版本在创建时有效，后续可被替代或退休。同谱系任一已提交状态至多有一个有效版本。

候选还有独立于调用请求的逻辑唯一约束：来源作用域和提案标识定位一个候选，内容绑定覆盖经验、适用范围、材料和修订前提。相同逻辑身份与相同内容返回原候选，内容不同则冲突；不靠换调用请求 ID 再建一份。不同逻辑提案的语义相似性仍由审查处理，不通过文本摘要自动合并。

审查事务须检查候选仍待审，并将候选终态、唯一决定、至多一个所产生的知识版本及成功回执一起提交。竞争的接受/拒绝至多一个生效；已决候选的等价请求返回原决定，改变决定方向、主体归因、理由或依据则冲突。错误决定需要引用原决定的后续候选或其他受支持操作纠正，不重新打开原候选，也不创建第二个准入版本。这与“同一谱系至多一个有效版本”是两项分别需要验证的约束。

修订接受时对预期当前版本作条件更新，旧版本退出主动查询、新版本生效与审查记录同事务提交；竞争者收到冲突，不覆盖胜出的版本。退休也核对原版本，不能把迟到决定应用到新版本。事务重放先返回已有成功结果，不能因当前版本已改变而把原成功请求重新解释成一次新操作。

初版不做跨谱系自动合并或自动重新激活。错误决定通过可追溯的新记录和受支持操作纠正，不改写已发生历史。

## Ledger 连接与恢复

采用 Ledger 的 `bounded-local-v0.1` 公共库：`initialize` 与 `open` 分离，写入使用 `execute`，定位对象使用 `get_record`，核对原请求使用 `get_operation`，实际内容使用 `read_blob` 校验读取。完整接口以[固定依赖文档](https://github.com/kongbu0621/infra-artifact-ledger/blob/58b08fa9cb188c48feec45592a0f775c7178fd7a/docs/INTERFACE_PROFILE.md)为准。

每个材料引用保存配置的 Ledger 绑定、Artifact ID、Version ID 与所用内容的摘要和大小。先核对 Version 属于指定 Artifact，再沿 ContentRoot/Manifest 定位 Blob 并读取实际字节；不从文件名、同名 ID 或 latest 推断内容。包自洽不能代替核对它属于调用方声明的任务。

当前初始化绑定调用方已确认的 Ledger Artifact 锚点及其完整不可变 metadata；每次材料操作重新核对。材料 task_ref 必须存在于 Version 的 external_source_refs；这是声明来源的一致性检查，不证明外部观察真实。锚点识别逻辑数据域，不是跨副本单写或防回滚证明；本轮没有提供恢复副本启用入口。

调用方可以提供已存在的材料版本；若本仓适配器负责登记材料，先持久保存原请求、稳定对象 ID、幂等键和有界输入字节，再分别提交 Ledger 的创建与追加操作。确认材料版本可读后，才提交引用它的知识记录。三次提交不是一个跨库事务；已登记但尚未被知识引用的材料允许保留。

任何丢响应或提交未知都保留原身份与内容，查询原操作并核对请求指纹及结果。一次未找到不证明旧调用不会继续提交；只在调用生命周期和原接口幂等语义允许时重试相同请求。不得换 key、删除数据库或重跑原生产任务来消除不确定性。

知识本地写操作也使用作用域、操作类型、请求 ID 与规范化内容绑定，成功回执与业务状态同事务保存；不能从 Ledger 的幂等性推断知识写入已幂等。错误返回需区分未提交、已提交和未知，重启按原请求查询或接续。

幂等重放先核对原请求内容，返回原对象与原提交事实，不重新执行领域迁移。K 回执同时与同事务保存的完整事件回执比较，防止只保留请求指纹却把结果引用换成另一对象。响应分别表达历史回执和当前状态观察：原知识后来退休、被替代或原材料损坏，不抹掉原提交，但也不能把重放标为当前仍可采用。当前观察失败时保留已核对的回执，单独返回缺口或未知；回执本身不一致仍拒绝。Ledger 的 `get_operation` 只核对历史成功记录与元数据，材料是否仍可读还须通过 `read_blob`；只读检查失败独立报告，不把它当成原操作未提交或自动产生新写入的理由。发布接续只以已核对的持久意图/回执及 Ledger 原操作为依据，失败诊断的报告读取不成为执行前置。

本地打开默认只读；仅 SQLite 明确报告热日志需要回滚时，对同一既有库以读写连接重开一次，让 SQLite 在自己的锁保护下恢复未提交页面。恢复后核对格式与身份，读取事务启用 query_only。活跃写入者的忙错误、坏格式及身份不符均不触发此回退；恢复所需权限或 I/O 不满足时保留原件并报告错误。该物理回滚不创建领域事件，也不等于恢复副本获准成为当前写入实例。

知识数据库只存本组件领域对象与引用，Ledger 保存原始材料；两者不共同写同一事实。完整知识文本随版本持久保存在知识库，后续若导出为制品，它是带版本的导出副本，不成为第二个可写的知识状态权威。

## 查询、使用与反馈

查询先按显式类型、范围与上下文条件确定性筛选有效知识；响应有界，返回准确版本、内容绑定和材料可用性。候选、被替代和退休版本只可从历史入口读取，不混入主动查询。首版不实现语义排名或可独立修改状态的缓存。

开始使用是单独的本地写操作：在事务中核对准确版本仍有效、适用条件匹配，并保存关联任务的稳定使用 ID。返回的知识内容与该版本一致。查询与开始使用之间发生退休或修订时，新使用应冲突；先登记成功、之后才退休时，保留原使用事实。调用方负责确保实际采用与登记对应，记录本身不证明外部业务已经执行。

使用登记重放返回同一使用 ID、原任务、原版本与原登记时间，明确是历史结果；另附的当前状态有本次观察依据或明确未知。新任务、新上下文或新的使用必须重新登记并检查当前有效性，不能复用旧回执延长知识有效性。原使用是否真的执行及用了哪些内容，仍由调用方的效果材料说明。

完成反馈使用原使用 ID，允许原知识版本已失效。先按材料适配流程保存并核对准确制品版本，再在一个知识事务内创建完成观察的运行材料记录、关联原使用的效果记录与成功回执。后续修订或退休引用这份运行材料记录，沿它追溯效果、原使用及制品；反馈不能止于使用统计。

同一使用只允许一个首次完成反馈，换请求 ID 不能追加第二次完成；等价请求返回原效果，不同内容冲突。更正必须引用该使用的上一条反馈并保留原内容，在事务中核对更正前提，避免两个更正互相覆盖；更正不改变原使用版本、不计成新使用，也不自动改知识状态。没有原使用 ID 的结果单独作为运行材料接收并标明关联缺口，不伪造效果关联。

若原件登记或读取尚未完成，保存本次已接收的有界输入、原请求及待决/失败状态，不把它标为可供准入引用的完整材料。确认后的材料和效果可以继续提交；已写入 Ledger 但知识事务未完成时按原身份接续，不重做原任务或丢弃已得到的效果。

P 可把生产候选与运行引用交给 K，并读取 K 的知识版本；双方通过可版本化的公共数据对象连接。K 不写 P 的任务状态，P 不直接设置 K 的有效状态。适配与真实消费验证后才能宣称两端已经接通。

## 持久性、隐私与资源

知识存储采用本地 SQLite，单次领域写事务内完成状态检查、事件与幂等结果。多个进程串行写入或得到明确忙错误；材料发布的 Ledger 写入放在 K 事务外。当前登记、提案及接受审查会在 K 写事务内完成有界的 Ledger 本地读取，保证本地前提与准入决定一起核对；它可能延长本地写锁持有时间，不提供远程 I/O 等待或跨库原子冻结。锁竞争有界返回忙错误，随后可沿原请求继续。外部内容核对与本地状态检查分别记录，新使用前仍需重新确认必需材料可读，之后的可用性变化如实报告。

运行数据放在调用方指定的私有目录；一个数据库属于一个受信、隐私和保留范围。主体标签与 namespace 不提供租户隔离。本地持久化不承诺加密、密码学防篡改或任意掉电恢复。

首次实现明确文本、记录、内容读取、查询分页及重试预算。遵守 Ledger 更严格的限额，超限报错，不截断经验或悄悄减少依据。初始化与打开既有库分离；缺库、损坏或不支持的格式不能自动变成空库。

## 组合恢复

知识状态与 Ledger 分别取得一致性快照；不能仅复制活动 SQLite 主文件而忽略 WAL。记录源知识库与快照身份、所覆盖的提交范围及 Ledger 绑定，快照时间不能单独证明业务状态最新。知识快照和 Ledger 快照不保证同时刻，恢复到新的隔离位置后应核对声明范围内的完整引用链，包括知识、审查、使用、候选、运行材料和效果记录实际引用的准确制品版本与所需内容。

缺失或损坏逐项呈现，限制依赖这些材料的准入和新使用；历史读取保留缺口。恢复检查不自动改变审查状态，不以同名材料或最新版本替代缺件。补齐并重新核对后才能声明该恢复点、该范围的引用完整；这项组合检查不要求重做 Ledger 已完成的 A2 任务。

恢复副本首先用于只读检查和历史读取，结果标明恢复点。即使其中某版本存储为有效，也只表示它在恢复点的状态；不能经普通主动查询或使用登记直接向新任务提供它。例如，K1 有效时取得知识快照，随后原库退休 K1；恢复旧快照时所有 Ledger 原件仍可读，引用核对可以通过，却不能因此恢复 K1 的当前有效性。检查本身不把整库知识自动退休，也不抹掉快照中的原审查事实。

把副本启用为当前知识库是单独的消费者切换。受信调用方须先确定实际恢复点与业务范围，核对可取得的后续修订、退休、使用、反馈及原请求结果，并处理影响本次启用的差异。不能覆盖已知的后续决定；快照中查不到请求也不证明快照后没有提交，不能据此重新执行原任务。原库或后续记录不可取得时，报告这一时间范围的未知和可能缺失；仅凭快照不能确认当前有效性的知识继续作为历史材料，待按显式审查与受支持操作处理后再用于新任务。

切换前停止或隔离同一知识库原实例的业务写入，并将消费者明确指向所选实例。两个副本各自的 SQLite 事务不能保证跨副本的唯一决定和幂等；同一逻辑知识库只允许一个当前写入实例，归档副本保留只读；多个本地进程仍可串行写同一当前数据库文件，限制的是独立副本而非进程数量。

若停写后取得的知识快照覆盖原库最终提交范围，且绑定、内容与引用核对通过，可以记录切换结果并启用，不要求重新审查原已准入知识。首版先验证隔离恢复及受控切换边界，不实现自动故障转移、多副本合并或分布式写入协调。具体启用操作和检查字段随首次实现定义；不把本次文档核对写成已完成消费者切换。

## 请求作用域兼容

`0.1.0a3` 的请求作用域统一限于 256 UTF-8 bytes；请求解析、原操作查询以及持久材料/使用/反馈记录都调用同一校验器。回执键仍为完整 scope、operation、request_id 的摘要，候选仍以完整 scope、proposal_id 去重；不改表结构、不截断键、不重写旧回执。较长名称仍计入整体请求与响应预算；使用新长度后，读写进程应保持在支持该长度的版本。
