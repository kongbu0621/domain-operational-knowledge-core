# 需求：运行经验成为可复用知识

状态：本文保留首版完整需求。当前 `0.1.0a3` 已实现 K1–K7 的材料、候选、审查、查询、准确版本使用/反馈、修订退休及原请求接续，提供独立库与 CLI。K8 已完成 P 的真实知识采用与反馈、明确学习候选投递、反馈驱动的修订及后续文档交付采用；已有试点的历史只读组合恢复也已核对。恢复副本受控启用、真实退休及独立 Generic Agent 消费仍待接续，不能由已有结果推断 Ledger A3 或完整生产资格完成。具体字段和范围见[公共接口](INTERFACE.md)，验证见[开发记录](DEVELOPMENT.md)。

## 使用者与目标

使用者是希望复用任务经验的人、应用和 Agent。已有成果记录可以保存材料，但不回答一条经验是否经过审查、适用于什么条件、哪一版仍可采用，以及后续使用是否产生反例。

本组件管理运行知识的生命周期。首个计划消费者包括 P 方向的生产控制流程；独立调用方应可通过同一公共接口使用，不依赖 P 的数据模型、聊天历史或特定模型服务。消费者仍负责其行动权限、实际执行和结果观察。

## 核心需求

| 编号 | 行为 | 可观察的结果 |
| --- | --- | --- |
| K1 | 保存运行材料的结构化记录 | 原任务、上下文、结果与准确制品引用可定位；声明的结果与观察缺口分开 |
| K2 | 接收有来源的候选 | 候选具有稳定提案身份，引用已有运行记录，包含经验内容和适用条件；待审时不作为可用知识返回 |
| K3 | 记录明确审查 | 同一候选只能形成一个最终接受或拒绝决定；接受产生知识版本，拒绝保留原因且不产生有效知识 |
| K4 | 查询并读取知识 | 返回当前有效且匹配适用条件的准确版本、内容及来源；历史版本通过独立读取入口访问 |
| K5 | 记录实际使用和效果 | 区分查询命中、开始采用和完成反馈；效果绑定原任务及确切使用版本 |
| K6 | 修订与退休 | 新材料支持修订或退休决定；旧版本退出主动查询，历史仍能解释原任务 |
| K7 | 重试与恢复 | 重试不增加重复材料、候选、决定或使用；冲突明确拒绝，重启保留原身份与待决状态 |
| K8 | 独立运行与组合核对 | 在独立环境通过库或 CLI 使用；识别恢复范围内的引用缺口和恢复点限制，核对通过不自动启用业务 |

## 首版范围和输入

当前实现为单机、离线优先、单个受信数据域。持久化目录由调用者选择，数据库在本地文件系统上活动写入。多个进程的请求可以串行化；不提供无协调的多机共同写库。

输入至少包含稳定请求标识、调用来源、任务/运行引用、原始材料的准确版本、经验内容、适用范围和必要的版本前提。当前字段与 JSON 形状见[公共接口](INTERFACE.md)，本版不提供网络协议。

首条知识流程采用调用方提供的经验文本和显式审查决定。K 可以检查结构、引用和状态前提，不能自动证明经验正确。审查授权由受信调用边界提供，首版的主体名称仅用于归因，不冒充认证系统。

## 关键语义

- 一次运行的成功或失败只能形成材料和候选，不能直接改变有效知识。
- 候选与审查对象固定内容版本；审查过程中内容改变，应成为新的明确候选，不能让旧决定批准新内容。
- 提案的逻辑身份与某次调用的请求标识分开。同一来源作用域、同一提案身份和相同内容应定位同一候选，换请求标识也不能重复创建；同一提案改内容必须冲突。作用域是去重边界，不是身份认证。
- 同一候选的接受与拒绝互斥；并发审查或换请求标识再次接受，均不能再产生一份知识。不同候选的观点相似仍属于审查判断，不声称自动完成语义去重。
- 对同一谱系，接受修订须核对预期的当前版本并原子切换；竞争修订不能产生两个有效版本。过期提案保留并报告冲突，由调用方重新提出。
- 退休需有依据和明确决定，保留历史；重新激活不在首版自动处理范围内。
- 查询结果不能永久保证知识仍有效。记录新使用时重新核对当前状态与适用条件；只有完成使用登记后才能将后续效果标为该次使用的反馈。
- 已登记使用后，知识即使被修订或退休，迟到反馈仍应关联原版本。使用记录不锁住知识，不为新任务延长旧版本的有效性，也不是行动许可。
- 重放使用登记返回原使用事实，不重新判定为一次当前有效的新使用。响应须区分原提交结果与本次观察到的知识状态、材料可用性；状态未知时明确呈现，不能将旧回执当作新的采用许可。
- 无原使用记录的迟到结果先作为运行材料保留，显式标出关联缺口；不丢弃结果或伪造先前使用凭据。
- 完成效果必须进入运行材料路径，才能被后续候选、修订或退休引用，不能只保存使用次数或一个结果标记。同一使用的首次完成反馈唯一；更正保留原反馈并显式关联，不计作又一次使用。
- 相同操作、请求标识与相同内容重试返回原结果；同一标识换内容拒绝。不同请求提出相似观点不等于已自动完成语义去重，审查需能看到来源与重复可能。
- 原件不可用与知识审查状态是不同事实。缺失内容不得冒充完整可用；准入和新使用所必需的材料缺失时拒绝依赖它的操作，历史仍可读取并显示缺口。
- 恢复快照保留恢复点的历史，不证明它包含后来发生的修订、退休、使用或反馈。引用完整不能使旧知识重新成为当前可用知识；恢复核对与消费者切换分开，同一知识库的原实例与恢复副本不能各自承接新的业务写入。

## 交付与验收

首版需完成一条可重启的真实消费流程：材料登记、候选隔离、明确审查、知识查询、实际采用、效果回流，以及一次有依据的修订或退休。只增加知识条目或只成功调用保存接口不能替代这条流程。

必须验证同请求重复、不同内容冲突、竞争修订、审查拒绝、使用中退休、迟到反馈、原件损坏及跨库引用缺失。替身验证与安装态实际链路分开记录。组合恢复只对已核对的恢复范围和恢复点作结论，不继承 Ledger 单库恢复成功作为知识引用完整的证明。还需覆盖旧知识快照引用齐全、但快照后已发生退休的反例；隔离恢复副本中的历史有效状态不能直接作为新使用依据。

K 实现或者与 P 组合不自动完成 Ledger A3。A3 中独立 Generic Agent 仍需自身的真实用途、独立调用与可核对结果。

## 不在首版范围

自动认定事实、自动知识准入、完整理论研究或数字自我、模型训练、向量检索平台、通用知识治理服务、多租户鉴权、远程服务、自动迁移旧原型数据。首版的知识状态不承担任务执行权限或生产验收职责。

## 请求作用域上限

Owner 已要求将请求作用域上限扩大到 256。原生 K scope 保留 UTF-8 字节计量，最多 256 bytes（ASCII 为 256 字符）；写入、查回执、待决接续和持久记录读取须一致。旧请求继续保留完整身份，不能截断名称或重建历史；稳定对象 ID 的限额不随之扩大。
