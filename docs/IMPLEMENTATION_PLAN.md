# 首版实施计划

状态：`0.1.0a3` 已实现第 1–3 步：领域核心与公共入口、Ledger 材料读写与原请求接续、使用/反馈/更正及修订/退休；合成和安装验证见[开发记录](DEVELOPMENT.md)。第 4 步已完成 P 真实采用/反馈、基于反馈的明确审查修订及后续本地文档交付采用/反馈，另有五个合成组合恢复窗口和所选真实试点的只读恢复；同机原路径受控启用和恢复后的新采用/反馈也已验证；真实退休、跨机切换及独立消费者仍待接续。需求见[需求文档](REQUIREMENTS.md)，状态与恢复约束见[架构](ARCHITECTURE.md)。

P 的首轮候选闭环和选定故障窗口已有现场记录，Owner 随后批准开始 K 第一轮核心实现，许可证采用 MIT。K 的完整实现不作为 P 使用可选知识端口的前置；本计划仍保留后续顺序，不代表已经部署知识网络服务。

## 1. 实现领域核心和公共入口

建立独立 Python 包、库和 CLI，确定公共操作、严格输入格式、错误及提交状态、资源限额。实现知识库初始化/打开、材料记录、候选、审查、准确版本读取和有界确定性查询。

候选提交、审查、知识状态与成功幂等回执从第一步具备事务约束。待审和被拒候选不能进入主动查询；相同请求换内容拒绝。实现前明确许可证、受信调用边界和采用的 Ledger 兼容版本，不继承旧原型版本或测试结论。

提案逻辑身份与调用请求身份分别建约束；审查检查同一候选的待审前提，不能仅靠请求幂等或知识谱系约束防止重复准入。返回结果区分历史重放与当前状态，历史成功不冒充当前材料可用。

验收：独立进程重启后可读取原记录；重复请求不产生第二条候选或知识；拒绝审查无有效知识副作用；错误输入和缺失引用不部分提交。

## 2. 接通 Ledger 材料与恢复

在独立安装环境使用 Ledger 公共库读取准确版本及实际内容；材料登记按原请求保存待决状态，覆盖创建成功、追加失败、回执丢失和知识引用提交失败。先用合成材料演练，不读取或迁移旧私有知识实例。

验收：精确引用和原始内容相符；未知写入按原身份核对；只完成 Ledger 写入时材料保留，知识库不假报引用成功；损坏字节和错误 Artifact/Version 配对被拒绝。

## 3. 完成使用、反馈、修订与退休

实现使用开始登记、原版本效果反馈、基于新材料的修订和退休。修订检查预期有效版本，切换同事务完成；反馈允许引用已登记使用的旧版本，不能给新任务延长旧知识有效性。

完成反馈同时形成可供候选引用的运行材料记录，保存原使用、效果和精确制品的关联；首次完成唯一，更正保留原反馈及明确前提。验证反馈保存后能够提出并审查一次修订，不能只验证反馈接口返回成功。材料登记中断时保留原输入与接续状态，不重新运行生产任务。

验收：两个竞争修订只有一个生效；查询后退休不能创建新使用；已开始使用的迟到反馈仍关联旧版本；无使用记录的结果保留为材料并显示缺口；效果统计不自动准入或退休知识。

## 4. 独立消费与组合恢复

选用已明确需求中的真实运行经验，通过实际调用方完成材料、审查、知识采用、效果和修订/退休闭环。与 P 的候选/知识端口做显式适配；独立调用测试不导入 P 的内部模块。

构建并在独立环境安装，核对实际导入与 CLI；补齐用户安装说明和 API 列表。验证知识库与 Ledger 的组合恢复：既覆盖 Ledger 快照早于知识快照的缺失引用，也覆盖知识快照早于后续退休、但原件仍齐全的情形。恢复副本先用于只读历史核对，明确恢复点和未知范围；定义受控启用的检查，处理已知后续决定并隔离原写入实例后才切换消费者，不因引用检查通过自动开放主动查询或新使用。

本次真实修订复用 P 已验收但未应用的 README 成果：本地调用方采用新版本后完成应用、验证与主干发布，并回流准确结果。没有新发 P 编辑任务，也没有为覆盖阶段而退休仍适用的知识；不将同一工作流的本地调用计为独立 Generic Agent 验收。新修订晚于旧只读恢复基线，旧副本中的 ACTIVE 仅描述恢复点，不能据此替代当前知识。

已完成的真实只读恢复保留 K 原路径，通过隔离命名空间读取副本，没有修改身份文件或私有表；该次核对当时没有切换。后来按明确授权在同一主机原路径启用包含最新修订/反馈的副本，将原实例移入 root 私有只读保留区；已验证原写入者退出和写入拒绝、新采用/反馈及重开后原请求复用。此为维护操作，不是产品新增自动启用接口；跨机切换、重启自动重建只读挂载仍未验收。后续真实任务与数据依据届时实际授权选取，原始证据留在私有位置，公开结论区分替身、安装态和真实消费。是否满足 Ledger A3 独立 Generic Agent 一侧，按实际消费者角色与使用证据判断，不能用建仓或两个脚本代替。

## 必要验证

| 场景 | 必须观察到的行为 |
| --- | --- |
| 候选未审或被拒 | 主动知识查询不返回它，历史仍可定位 |
| 接受决定已提交但回执丢失 | 原请求返回原知识版本，不重新准入 |
| 同请求换内容 | 冲突，不改变历史 |
| 同一逻辑提案换调用请求标识 | 相同内容返回同一候选，不同内容冲突；不同逻辑提案不被擅自按相似文本合并 |
| 同一候选重复接受或接受/拒绝竞速 | 至多一个终态决定、至多一个准入版本；等价请求返回原结果，矛盾决定不覆盖 |
| 两个修订基于同一旧版本 | 至多一个新版本有效，另一个收到可解释冲突 |
| 查询后知识被退休 | 新使用登记被拒绝，历史查询保留 |
| 使用登记后退休、效果迟到 | 反馈关联原使用和版本，不重新激活知识 |
| 使用登记回执丢失，退休后再重放 | 返回原使用及历史标识，当前状态另行呈现；不新增使用、不暗示当前仍有效 |
| 无原使用记录的效果 | 保留材料与关联缺口，不伪造先前凭据 |
| 完成反馈后提出修订 | 新候选可引用效果形成的运行材料，追溯原使用及制品，不能仅有计数 |
| 换请求标识重复完成或并发更正 | 首次完成唯一，更正核对前提并保留历史，不新增使用次数 |
| Ledger 写入完成，知识写入未完成 | 保留制品和待决请求，按原身份接续 |
| 原材料损坏、缺失或版本错配 | 明确拒绝依赖该内容的操作，不替换为最新版本 |
| 历史成功仍可查询、原内容已损坏 | 保留原提交事实，单独报告当前不可用，不把历史回执当内容验证 |
| 两库各自恢复成功但引用缺失 | 报组合范围不完整，准入状态不被自动改写 |
| 旧知识快照引用齐全，但之后已经退休 | 可通过该恢复点的引用核对；恢复副本只读呈现历史，不自动开放主动查询或新使用，也不回滚已知退休 |
| 原库不可取得，或快照后原请求结果未知 | 报恢复点后的未知范围，未找到不等于未提交；保留历史与待核对状态，不重跑原任务 |
| 停写后取得完整快照，引用核对通过 | 显式切换消费者后可使用所选当前库；旧实例保持停止或只读，不要求重复准入已有知识 |
| 原实例尚在承接写入时切换恢复副本 | 不启用第二个当前写入实例；先停止或隔离原写入，再按所选恢复点和处理结果切换 |
| 进程退出、忙错误或重启 | 原提交与未决状态可核对，不自动初始化新库 |
| 预算或输入限额超出 | 明确失败，不截断内容或无限重试 |

当前代码验证覆盖材料、候选、审查、查询、使用/反馈、更正、修订/退休、原请求幂等、竞争及中断接续；编译、事务、进程故障注入、安装和真实消费分别记录。尚未实现的组合恢复和真实消费场景不能预先标为通过。
