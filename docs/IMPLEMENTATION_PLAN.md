# 首版实施计划

状态：建仓和设计阶段，尚无产品实现。需求见[需求文档](REQUIREMENTS.md)，状态与恢复约束见[架构](ARCHITECTURE.md)。

K 先建立清晰入口，工程推进仍先完成 P 的首版核心；K 的完整实现不作为 P 使用可选知识端口的前置。本计划规定开始 K 实现时的顺序，不代表已部署知识服务。

## 1. 实现领域核心和公共入口

建立独立 Python 包、库和 CLI，确定公共操作、严格输入格式、错误及提交状态、资源限额。实现知识库初始化/打开、材料记录、候选、审查、准确版本读取和有界确定性查询。

候选提交、审查、知识状态与成功幂等回执从第一步具备事务约束。待审和被拒候选不能进入主动查询；相同请求换内容拒绝。实现前明确许可证、受信调用边界和采用的 Ledger 兼容版本，不继承旧原型版本或测试结论。

验收：独立进程重启后可读取原记录；重复请求不产生第二条候选或知识；拒绝审查无有效知识副作用；错误输入和缺失引用不部分提交。

## 2. 接通 Ledger 材料与恢复

在独立安装环境使用 Ledger 公共库读取准确版本及实际内容；材料登记按原请求保存待决状态，覆盖创建成功、追加失败、回执丢失和知识引用提交失败。先用合成材料演练，不读取或迁移旧私有知识实例。

验收：精确引用和原始内容相符；未知写入按原身份核对；只完成 Ledger 写入时材料保留，知识库不假报引用成功；损坏字节和错误 Artifact/Version 配对被拒绝。

## 3. 完成使用、反馈、修订与退休

实现使用开始登记、原版本效果反馈、基于新材料的修订和退休。修订检查预期有效版本，切换同事务完成；反馈允许引用已登记使用的旧版本，不能给新任务延长旧知识有效性。

验收：两个竞争修订只有一个生效；查询后退休不能创建新使用；已开始使用的迟到反馈仍关联旧版本；无使用记录的结果保留为材料并显示缺口；效果统计不自动准入或退休知识。

## 4. 独立消费与组合恢复

选用已明确需求中的真实运行经验，通过实际调用方完成材料、审查、知识采用、效果和修订/退休闭环。与 P 的候选/知识端口做显式适配；独立调用测试不导入 P 的内部模块。

构建并在独立环境安装，核对实际导入与 CLI；补齐用户安装说明和 API 列表。验证知识库与 Ledger 的组合恢复，尤其是 Ledger 快照早于知识快照的缺失引用情形；核对范围和缺口必须可定位。

真实任务与数据依据届时实际授权选取，原始证据留在私有位置，公开结论区分替身、安装态和真实消费。是否满足 Ledger A3 独立 Generic Agent 一侧，按实际消费者角色与使用证据判断，不能用建仓或两个脚本代替。

## 必要验证

| 场景 | 必须观察到的行为 |
| --- | --- |
| 候选未审或被拒 | 主动知识查询不返回它，历史仍可定位 |
| 接受决定已提交但回执丢失 | 原请求返回原知识版本，不重新准入 |
| 同请求换内容 | 冲突，不改变历史 |
| 两个修订基于同一旧版本 | 至多一个新版本有效，另一个收到可解释冲突 |
| 查询后知识被退休 | 新使用登记被拒绝，历史查询保留 |
| 使用登记后退休、效果迟到 | 反馈关联原使用和版本，不重新激活知识 |
| 无原使用记录的效果 | 保留材料与关联缺口，不伪造先前凭据 |
| Ledger 写入完成，知识写入未完成 | 保留制品和待决请求，按原身份接续 |
| 原材料损坏、缺失或版本错配 | 明确拒绝依赖该内容的操作，不替换为最新版本 |
| 两库各自恢复成功但引用缺失 | 报组合范围不完整，准入状态不被自动改写 |
| 进程退出、忙错误或重启 | 原提交与未决状态可核对，不自动初始化新库 |
| 预算或输入限额超出 | 明确失败，不截断内容或无限重试 |

当前只有文档，检查链接、术语、来源和范围即可；实现后的编译、事务、故障注入、安装和真实消费验证分别记录，不能预先标为通过。
